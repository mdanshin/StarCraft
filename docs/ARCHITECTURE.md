# Архитектура

Версия 0.2 запускается двойным щелчком по `Play.html`. CSS, данные и JavaScript включены в HTML; иллюстрации читаются из соседней папки `assets`. Запросы `fetch` и ES-модули при таком запуске не используются. Для разработки исходников доступны Node.js 20+ и современный браузер. `node scripts/serve.mjs` обслуживает статические файлы только на 127.0.0.1. Интернет для игры после загрузки репозитория не нужен.

| Файл | Ответственность |
| --- | --- |
| `data/cards.json` | Единственная исполняемая база карт |
| `scripts/make-data.mjs` | Читаемый источник карточных параметров, генерация JSON |
| `src/engine.js` | Проверка приказа и детерминированный переход состояния |
| `Play.html` / `scripts/build-desktop.mjs` | Воспроизводимая автономная сборка без внешнего сборщика |
| `src/bot.js` | Выбор допустимого приказа, экономика, технологии и бой учебного соперника |
| `src/saves.js` | Формат сохранений, проверка структуры и ссылок, импорт версии 0.1 |
| `src/app.js` | Отображение, выбор целей, фильтры, локальное сохранение |
| `src/style.css` | Рамки, интерфейс, адаптация под размеры экрана |
| `scripts/render-print.py` | SVG-карты, рубашки, PDF, жетоны |
| `tests/engine.test.mjs` | Контракты экономики, боя, технологий и партия до победы |

Основной контракт: `createEngine(cards).act(state, action) -> newState`. Исходное состояние не изменяется. Недопустимый приказ выбрасывает `RuleError`; вызывающий код сохраняет старое состояние. ID единиц и очередей монотонны и не переиспользуются. Генератора случайных чисел в версии 0.1 нет.

`state` содержит игроков, юнитов/здания, очереди, счётчик цикла, инициативу, остаток приказов, сканы, журнал и победителя. Карточный ID описывает тип, ID сущности — конкретный экземпляр. Производственная очередь ссылается на ID производителя или строящегося здания; его уничтожение удаляет связанную очередь. Использованный и доступный лимит вычисляются из сущностей и очередей, а не дублируются изменяемыми счётчиками.

Сохранение в `localStorage` — удобство локальной партии. Обёртка `koprulu-save` хранит состояние, режим и настройку тумана. Импорт проверяет пределы чисел, карты, владельцев, ID и связи очередей; ошибка не заменяет текущую партию. При запрете хранилища игра продолжает работать и предлагает сохранение в файл. Экспорт JSON — снимок, не полноценный реплей. Полный replay потребует начальной версии набора и последовательности действий. Клиент 0.1 имеет всё состояние; фильтрация видимости предназначена для совместного тестирования.

Сетевой этап переносит `act` на авторитетный сервер. Команда содержит matchId, playerId, ожидаемую версию и nonce. Сервер проверяет активного игрока, версию и допустимость действия, атомарно сохраняет новое состояние, возвращает только проекцию игрока. Повтор nonce не выполняет приказ второй раз. Серверный журнал скрыт до окончания партии. Одинаковые действия на одинаковой версии данных должны давать одинаковый хеш.

Нельзя начинать сетевой этап с синхронизации двух полных клиентских состояний: это раскроет туман войны и даст право клиенту менять ресурсы. Сначала стабилизировать контракты движка, затем транспорт и интерфейс.

## Компьютерный соперник и очередь интерфейса

`chooseBotAction(engine, state)` детерминированно ранжирует варианты и проверяет их обычным `engine.act`. Планирование не изменяет исходное состояние. В оценке целей участвуют только видимые враги; расположение стартовых баз известно из карты. Ресурсы, сроки и число приказов совпадают с человеческими. Уровень один, учебный; оценки боёв и технологический план упрощены.

В одиночном режиме перспектива экрана закреплена за игроком 0. При активном игроке 1 кнопки приказов блокируются, ход выполняется через короткий таймер. Номер экземпляра партии и отмена таймера защищают новую/загруженную партию от старого отложенного хода. После перезагрузки прерванный ход компьютера продолжается. В режиме для двоих перспектива меняется с активным игроком.

`npm run check:desktop` сравнивает собранный `Play.html` с источниками. `tests/browser-smoke.mjs` проверяет именно запуск через `file://` с отключёнными сетью и `fetch`, а также изображения, туман, блокировку приказов, импорт/экспорт, автосохранение и отсутствие хранилища. Сценарий GitHub Actions основан на [официальной инструкции Playwright](https://playwright.dev/docs/ci-intro).
