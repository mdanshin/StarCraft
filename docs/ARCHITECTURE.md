# Архитектура

Прототип запускается локально без установки npm-зависимостей: Node.js 20+ и современный браузер. `node scripts/serve.mjs` обслуживает статические файлы только на 127.0.0.1. Интернет для игры после загрузки репозитория не нужен.

| Файл | Ответственность |
| --- | --- |
| `data/cards.json` | Единственная исполняемая база карт |
| `scripts/make-data.mjs` | Читаемый источник карточных параметров, генерация JSON |
| `src/engine.js` | Проверка приказа и детерминированный переход состояния |
| `src/app.js` | Отображение, выбор целей, фильтры, локальное сохранение |
| `src/style.css` | Рамки, интерфейс, адаптация под размеры экрана |
| `scripts/render-print.py` | SVG-карты, рубашки, PDF, жетоны |
| `tests/engine.test.mjs` | Контракты экономики, боя, технологий и партия до победы |

Основной контракт: `createEngine(cards).act(state, action) -> newState`. Исходное состояние не изменяется. Недопустимый приказ выбрасывает `RuleError`; вызывающий код сохраняет старое состояние. ID единиц и очередей монотонны и не переиспользуются. Генератора случайных чисел в версии 0.1 нет.

`state` содержит игроков, юнитов/здания, очереди, счётчик цикла, инициативу, остаток приказов, сканы, журнал и победителя. Карточный ID описывает тип, ID сущности — конкретный экземпляр. Производственная очередь ссылается на ID производителя или строящегося здания; его уничтожение удаляет связанную очередь. Использованный и доступный лимит вычисляются из сущностей и очередей, а не дублируются изменяемыми счётчиками.

Сохранение в `localStorage` — удобство локальной партии. Экспорт JSON — снимок, не полноценный реплей. Полный replay потребует начальной версии набора и последовательности действий. Клиент 0.1 имеет всё состояние; фильтрация видимости предназначена для совместного тестирования.

Сетевой этап переносит `act` на авторитетный сервер. Команда содержит matchId, playerId, ожидаемую версию и nonce. Сервер проверяет активного игрока, версию и допустимость действия, атомарно сохраняет новое состояние, возвращает только проекцию игрока. Повтор nonce не выполняет приказ второй раз. Серверный журнал скрыт до окончания партии. Одинаковые действия на одинаковой версии данных должны давать одинаковый хеш.

Нельзя начинать сетевой этап с синхронизации двух полных клиентских состояний: это раскроет туман войны и даст право клиенту менять ресурсы. Сначала стабилизировать контракты движка, затем транспорт и интерфейс.
